なぜ GitHub に賭けたか

個人開発の一番の弱点は属人化だ。自分が倒れたら全部止まる。だから、履歴と自動化を一箇所に集めて、未来の自分への引き継ぎ書にした。

§1手作業を構造で殺す

デプロイを手でやっている限り、いつか手が滑る。ワークフローに握らせれば、ミスは構造的に減る。

  • 履歴 = 過去の自分の判断の記録
  • Actions = 未来の自分の代わりに働く手
  • Issue = 忘れてもいい場所

覚えておくのをやめる。覚えなくていい仕組みに寄せる。
