The first thing I decide when designing a kids' app

2026-05-08

When I start a new app for kids, I write one line on paper before anything else: "How should the child feel after using this?"

For "Todo Gacha," I wrote: "The annoying morning routine should feel a little exciting." That single line makes every later decision easy.

"Should we add reward stickers?" If they make the routine more exciting, yes. If not, drop them. That's it.

Starting from features instead always leads me astray. "It's useful," "other apps have it" — features pile up, and suddenly the app is about nothing in particular.

The time spent on that one line matters more than the time spent coding.
